📋  Document 01
Product Requirements Document (PRD)

The north star of the entire project. Defines what we're building, who it's for, and what success looks like.
App Overview


App Name

Campus Art Fest Management System

Tagline

Your College Arts Festival — Tracked, Celebrated, Remembered

Purpose

A web app to manage programmes, student results, team scores, and winner posters for a campus arts festival, with fully real-time sync between admin edits and everything students/audience see

Primary Users

Students, Teachers, Audience, Fest Admin

Platform

Web (mobile-responsive), accessible on any device
The Problem We're Solving
Results and winners are announced verbally or on paper — easy to lose
No central place for students to check their programme results
Team scores are manually tracked — no live visual display
Downloading winner certificates/posters is not possible currently
Admin has no easy panel to update data without coding knowledge
When a result changes, nothing else updates automatically — old totals and pages go stale  [NEW]
Target Users


Students / Candidates

Check their participated programmes, see results, download their result poster

Audience / Visitors

Browse programmes, see team scores and competition winners, browse and download spotlight photos

Admin / Coordinator

Add programmes, update results, manage spotlight photos — team points are calculated automatically

Teachers / Jury

View results by category, see programme completion status
Core Features — Must Have
🏠 Section 1: Home / Spotlight
Auto-scrolling or fading hero banner of campus art fest photos
Only images an admin has "toggled on" appear in the hero banner — not every uploaded photo  [NEW]
Below the banner: a full scrollable gallery of ALL uploaded spotlight images — each can be selected and downloaded by any visitor  [NEW]
Team score bars for all 3 teams, with the current point total shown directly on/above each bar
Score bars animate (count up / fill in) every time the page loads or is refreshed  [NEW]
Short "About the Fest" section
4 quick-nav tiles: Teams, Students, Programmes, About
🏆 Section 2: Teams & Scores
3 teams displayed with curved/arc score bar per team, team name inside each bar
Team total points are calculated automatically as the sum of all points that team's students have won across all results — admin never edits a team total directly  [CHANGED]
Click any team → opens 3 sub-tabs: 1st Place Wins, 2nd Place Wins, 3rd Place Wins  [CHANGED]
Each sub-tab lists every programme where that team placed at that position, with the points earned  [NEW]
Tap a listed programme → see full result detail for that programme
Download winner poster in 3 design themes
👤 Section 3: Students / Candidates
Name search bar with filter by Team Name and Class Category
Click any student → Student Profile Card opens

Circular progress bar showing e.g. 4/7 programmes participated, animated on load/refresh  [CHANGED]
Total points the student has personally earned, shown alongside the progress ring  [NEW]

Download result poster in 3 design themes

List of all announced results, with an Edit button to reopen and change any result  [NEW]

All changes reflect live (or on next refresh) across Home, Teams, Programmes, and Student profiles  [NEW]
Real-Time Sync — Cross-Section Consistency
Worked example, straight from the v2 notes: editing one result must correctly cascade everywhere it's shown.
If an admin sets the result for "Elocution English (HS category)" as: 1st — Farhan Musthafa, Team A, 7 points · 2nd — Aslam Musthafa, Team B, 4 points · 3rd — Ali Abbas, Team C, 2 points — then without any other admin action:
Home page: Team A's score bar rises to reflect +7 points, and the new total is shown on the bar (Team B +4, Team C +2)
Teams page: Team A's "1st Place Wins" sub-tab now lists Elocution English (7 pts). Team B's "2nd Place Wins" sub-tab lists it (4 pts). Team C's "3rd Place Wins" sub-tab lists it (2 pts)
Programmes page: Elocution English now shows Finished ✅ with the full 1st/2nd/3rd breakdown
Students page: Farhan Musthafa's profile shows 1st in Elocution English (7 pts) under Completed; same for Aslam Musthafa (2nd, 4 pts) and Ali Abbas (3rd, 2 pts)

Technical Requirements Document (TRD)

The technical blueprint. Locks in every stack decision so AI and developers build consistently.
Tech Stack


Frontend Framework

React 18 (Vite) with JavaScript

Styling

Tailwind CSS + custom CSS for animations

Routing

React Router v6 (multi-page navigation, incl. nested tab routes for Teams and Student sub-pages)

State Management

React useState / useContext (no Redux needed)

Database

Supabase (PostgreSQL, real-time)

Real-time sync

Supabase Realtime channels — subscribe to results & teams tables so Home/Teams/Programmes/Students update live  [NEW]

File Storage

Supabase Storage (student photos, spotlight images)

Authentication

Supabase Auth — email/password for admin only

Hosting

Vercel or Netlify (Supabase does not host frontends)

Poster Download

html2canvas + file-saver (convert HTML poster to PNG)

Animated counters/bars

react-countup (or CSS transition + requestAnimationFrame) for score bars & progress rings  [NEW]

Icons

Lucide React

Build Tool

Vite (fast dev server, optimized build)
Supabase Tables (Database)


students

All student/candidate records

programmes

All fest programmes/events

results

Result entries per programme — now stores per-placement points  [CHANGED]

teams

Team names, colors — totalPoints is a derived/computed value, not stored input  [CHANGED]

spotlight

Home banner + gallery image URLs, with a featured/toggle flag  [CHANGED]

admin

Admin credentials (managed by Supabase Auth)
Third-Party Libraries


html2canvas

Renders the poster HTML div as a canvas image for download

file-saver

Triggers browser file download (saveAs function)

react-circular-progressbar

Circular progress bar for student programme count

react-countup

Animates score bars and percentage counters on load/refresh  [NEW]

react-router-dom

Page routing between sections, including tab-style sub-routes

lucide-react

Clean icon set (search, download, check, x icons)

@supabase/supabase-js

Full Supabase SDK (Database, Storage, Auth, Realtime)
Environment Variables (.env)
Store these in a .env file — never commit to GitHub:
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
Key Technical Constraints
Must be fully mobile-responsive — students will use phones
Poster download must work on mobile Chrome/Safari
Team totals and student progress must never be hand-edited in the database — always derived from results, so they can't drift out of sync  [NEW]
Admin panel route must be protected — redirect if not logged in
Student photos stored in Supabase Storage — not embedded as base64 in the database
Spotlight images: gallery shows all uploads; hero banner shows only toggled ones — one boolean field drives both views  [NEW]
Free Supabase tier limits — max 1GB database, 2GB storage, 50MB file size — sufficient for college fest

Step 2

Edge Cases & States


No results found in search

Programme not conducted yet

Backend Schema — Supabase Data Model

Every Supabase table, every column, every relationship — defined before writing a single database call.
Table: students


id

uuid — auto-generated Supabase row ID

name

string — full name e.g. 'Arjun K'

class_category

string — one of HS, Minor, Premier, Sub-junior, Junior

team

string — ref to teams table: 'team_A', 'team_B', 'team_C'

photoURL

string — Supabase Storage public URL

programmeIds

array<uuid> — programme IDs the student is enrolled in

totalPoints

computed — SUM of points from results where this student placed  [NEW]

createdAt

timestamp
Table: programmes


id

uuid — auto-generated Supabase row ID

name

string — e.g. 'Elocution English'

category

string — HS, Minor, Premier, Sub-junior, Junior

isFinished

boolean — true = Finished ✅, false = Pending ❎

resultId

uuid | null — ref to results row (null if not finished)

createdAt

timestamp
Table: results
One row per programme result. Linked from programmes.resultId.


id

uuid — auto-generated Supabase row ID

programmeId

uuid — ref to programmes

first

jsonb — { studentId, points }  [CHANGED]

second

jsonb — { studentId, points }  [CHANGED]

third

jsonb — { studentId, points }  [CHANGED]

updatedAt

timestamp — last time admin updated result
v1 used a single fixed formula (1st×5, 2nd×3, 3rd×1). v2 stores points per placement directly, set by the admin per programme — confirm this is the model you want before building.
Table: teams
Exactly 3 rows — one per team. Point totals are never written directly.


id

string — e.g. 'team_A', 'team_B', 'team_C'

name

string — team display name e.g. 'Red Eagles'

color

string — hex color for UI e.g. '#EF4444'

firstPlaceCount

computed — count of results where a team member placed 1st

secondPlaceCount

computed — count of results where a team member placed 2nd

thirdPlaceCount

computed — count of results where a team member placed 3rd

totalPoints

computed — SUM of all points earned by this team's students across results  [CHANGED]
Recommended: implement as a Postgres view (team_totals) or a database trigger on results INSERT/UPDATE, so totals can never drift out of sync with individual results.
Table: spotlight


id

uuid — auto-generated Supabase row ID

imageURL

string — Supabase Storage public URL

caption

string | null — optional caption text

isFeatured

boolean — true = shown in home hero banner; false = gallery-only  [NEW]

order

number — display order in slider/gallery

uploadedAt

timestamp
Table: admin
Managed by Supabase Auth. No separate custom table required — use auth.users with an admin role claim, or a minimal profile row.


email

string — admin login email

role

string — 'admin'

lastLogin

timestamp
Supabase Row Level Security (Summary)
students, programmes, results, teams, spotlight — PUBLIC READ, admin write only
team totals / student totals — read-only computed views, no direct write policy needed
Supabase Storage — public read for photos, admin write only
Admin authentication via Supabase Auth (email/password)
Data Relationships Diagram
students.programmeIds → programmes.id
programmes.resultId → results.id
results.first/second/third.studentId → students.id
students.team → teams.id
teams.totalPoints ← SUM(results.*.points) where results.*.studentId ∈ students of that team

Implementation Roadmap

Step-by-step build order. Follow this sequence and you'll never be stuck wondering 'what next?'
Phase 1 — Project Setup (Day 1)
Create React app with Vite: npm create vite@latest artfest --template react

Create folder structure: /components, /pages, /supabase, /hooks, /utils

Create supabase/client.js — initialize Supabase client
Create the results table with jsonb first/second/third {studentId, points} columns
Build a Postgres view or trigger for team_totals and student_totals so they're always derived, never manually set
Create supabase/queries.js — helper functions (getStudents, getProgrammes, getTeamTotals, etc.)
Seed Supabase tables with test data: 2–3 students, 3 programmes, 3 teams
Test all read operations, including the computed totals, work before building UI

Build App layout with bottom nav bar (Home, Teams, Students, Programmes)

Add dot indicators, pause on hover

Add 4 quick-nav icon tiles below
Phase 5 — Teams Section (Day 3–4)
Build 3 team cards with SVG arc/semicircle score bars fed by team_totals

Phase 6 — Students Section (Day 4–5)
Build student search bar with real-time filtering

Phase 7 — Programmes Section (Day 5)
Build programmes search + category filter

Click programme → Programme Result page showing 1st/2nd/3rd with photos + points

Phase 8 — Admin Panel (Day 6–7)

Phase 10 — Deployment (Day 8)

Deploy /dist to Vercel or Netlify (Supabase does not host frontends)
Share live URL with college
Test live URL on multiple phones
